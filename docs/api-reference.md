# API Reference

This document is the implementation contract for the Flutter client. Interactive OpenAPI documentation is also available at `/docs` on a running API.

## Base URL and authentication

- Local default: `http://localhost:8080/api`
- AWS: `{ApiUrl stack output}/api`
- Authentication: `Authorization: Bearer <cognito-access-token>`
- Public endpoints: `/`, `/docs`, `/openapi.json`, and `GET /api/health/check`
- All finance endpoints require a Cognito **access token**. An ID token is rejected.

The backend derives the user exclusively from the verified Cognito `sub`. Never send a `user_id` in a request body or query.

## Shared conventions

### Response envelope

Every successful request returns:

```json
{
  "success": true,
  "code": "FIN_TRANSACTION_CREATED",
  "message": "Transaction created successfully.",
  "errors": null,
  "result": {},
  "request_id": "34bbe068-99aa-460a-971f-2969304750b9"
}
```

Every failed request uses the same shape:

```json
{
  "success": false,
  "code": "FIN_TRANSACTION_NOT_FOUND",
  "message": "Transaction was not found.",
  "errors": null,
  "result": null,
  "request_id": "34bbe068-99aa-460a-971f-2969304750b9"
}
```

Do not infer success from `message`; use the HTTP status and `success`. Display `message` to the user when appropriate and include `request_id` in support/debug reports.

### Headers

Responses include:

- `X-Request-ID`: generated by the server or echoed from the request.
- `X-Response-Time`: server processing time, such as `24ms`.

The client may send an `X-Request-ID` UUID to correlate one user action across frontend and backend logs.

### Data formats

| Concept | Contract |
|---|---|
| Money | Integer minor units. `12345` USD means `$123.45`. Never send floating-point money. |
| Currency | Three-letter uppercase ISO-style code, currently demonstrated with `USD`. |
| Date | `YYYY-MM-DD`, for example `2026-10-13`. |
| Timestamp | UTC ISO-8601 string returned by the server. |
| Month | `YYYY-MM`, for example `2026-10`. |
| IDs | Opaque strings, normally UUIDs. Do not parse them. |
| Budget utilization | Non-negative decimal ratio; it can exceed `1.0` when spending is over budget. Multiply by 100 for display. |
| Extraction/forecast confidence | Decimal ratio from `0.0` to `1.0`; multiply by 100 for display. |
| Pagination cursor | Opaque string. Return it unchanged as the next request's `cursor`. |

Persist and calculate money as integers in Flutter. Convert to localized display only at the presentation boundary.

### Common entity metadata

Finance entities can include:

```json
{
  "entity_type": "TXN",
  "created_at": "2026-10-13T15:33:13.905557+00:00",
  "updated_at": "2026-10-13T15:33:13.905557+00:00",
  "version": 1
}
```

Treat unknown response fields as forward-compatible additions.

## Endpoint summary

| Method | Path | Purpose |
|---|---|---|
| GET | `/health/check` | API liveness; no authentication. |
| GET | `/auth/me` | Return the authenticated Cognito identity. |
| GET / PUT | `/profile` | Read or create/update finance preferences. |
| POST | `/demo/seed` | Replace the current user's data with deterministic demo data. |
| GET | `/accounts` | List account balances. |
| GET / POST | `/transactions` | List or create transactions. |
| PATCH | `/transactions/{transaction_id}` | Correct category, merchant, or notes. |
| GET / PUT | `/budgets/{month}/{category}` | Read or update one category budget. |
| GET / POST | `/bills` | List or create scheduled bills/income. |
| PATCH | `/bills/{bill_id}` | Update a bill. |
| GET | `/dashboard` | Aggregated dashboard for a month. |
| GET | `/forecast` | Deterministic cash-flow forecast. |
| POST | `/receipts/scan` | Upload and parse a receipt. |
| GET / PATCH | `/receipts/{receipt_id}` | Read, correct, or confirm a receipt. |
| POST | `/chat` | Send an assistant message. |
| GET | `/conversations/{conversation_id}` | Retrieve a conversation and messages. |

All paths below are relative to `/api`.

## Identity

### `GET /auth/me`

Response `result`:

```json
{
  "user_id": "cognito-sub",
  "email": "person@example.com",
  "username": "person@example.com",
  "scopes": ["openid", "email", "profile"],
  "groups": []
}
```

`email` and `username` are nullable because standard Cognito access tokens do not always contain those claims. Use the ID token locally for display-only profile claims; never send it to this API.

## Profile and demo data

### `GET /profile`

Returns `404 FIN_PROFILE_NOT_FOUND` until the profile is created or demo data is seeded.

### `PUT /profile`

```json
{
  "currency": "USD",
  "timezone": "Asia/Karachi",
  "monthly_income_minor": 500000,
  "opening_balance_minor": 240000,
  "safety_buffer_minor": 75000
}
```

All fields have defaults, but the frontend should send the complete settings form. Success code: `FIN_PROFILE_UPDATED`.

### `POST /demo/seed`

No request body. Response:

```json
{
  "seeded": true,
  "item_count": 20
}
```

**Destructive behavior:** this endpoint deletes all finance data in the authenticated user's partition before inserting demo data. The UI must show a confirmation dialog and must expose this action only in demo/development builds.

## Accounts and transactions

### `GET /accounts`

Response `result` is an array:

```json
[
  {
    "entity_type": "ACCOUNT",
    "account_id": "checking",
    "name": "Everyday Checking",
    "account_type": "checking",
    "balance_minor": 240000,
    "currency": "USD",
    "created_at": "...",
    "updated_at": "...",
    "version": 1
  }
]
```

### `GET /transactions`

Query parameters:

| Name | Type | Default | Notes |
|---|---|---|---|
| `start_date` | date | 60 days before `end_date` | Inclusive. |
| `end_date` | date | Today | Inclusive. |
| `category` | string | none | Exact category match. |
| `transaction_type` | string | none | `income`, `expense`, `transfer`, or `refund`. |
| `limit` | integer | 100 | Range `1..200`. |
| `cursor` | string | none | Opaque cursor from the prior response. |

Response:

```json
{
  "items": [
    {
      "entity_type": "TXN",
      "transaction_id": "uuid",
      "account_id": "checking",
      "amount_minor": 8450,
      "currency": "USD",
      "transaction_type": "expense",
      "category": "groceries",
      "merchant": "Fresh Market",
      "posted_at": "2026-10-11",
      "source": "manual",
      "notes": null,
      "receipt_id": null,
      "created_at": "...",
      "updated_at": "...",
      "version": 1
    }
  ],
  "next_cursor": null
}
```

When `next_cursor` is non-null, append the next page rather than replacing existing rows. Changing filters invalidates the previous cursor.

### `POST /transactions`

```json
{
  "account_id": "checking",
  "amount_minor": 3250,
  "currency": "USD",
  "transaction_type": "expense",
  "category": "dining",
  "merchant": "Corner Cafe",
  "posted_at": "2026-10-13",
  "source": "manual",
  "notes": "Lunch"
}
```

- `amount_minor` must be greater than zero; direction comes from `transaction_type`.
- `account_id` defaults to `checking`.
- `source` is one of `manual`, `seed`, `receipt`, or `agent`; normal UI entry should use `manual`.
- Success status is `201` with code `FIN_TRANSACTION_CREATED`.

### `PATCH /transactions/{transaction_id}`

Send at least one editable field:

```json
{
  "category": "groceries",
  "merchant": "Fresh Market",
  "notes": "Weekly shop"
}
```

Amount, type, account, date, source, and receipt linkage are not editable through this endpoint.

## Budgets

### `GET /budgets/{month}/{category}`

Example: `GET /budgets/2026-10/dining`.

Response `result`:

```json
{
  "month": "2026-10",
  "items": [
    {
      "entity_type": "BUDGET",
      "month": "2026-10",
      "category": "dining",
      "limit_minor": 30000,
      "currency": "USD",
      "spent_minor": 10600,
      "remaining_minor": 19400,
      "utilization": 0.3533,
      "created_at": "...",
      "updated_at": "...",
      "version": 1
    }
  ]
}
```

An unknown category currently returns an empty `items` array rather than `404`.

### `PUT /budgets/{month}/{category}`

```json
{
  "limit_minor": 30000,
  "currency": "USD"
}
```

The backend normalizes the path category to lowercase. Success code: `FIN_BUDGET_UPDATED`.

## Bills and scheduled income

### `GET /bills?days=30`

`days` accepts `1..365`. The response is an array of active bills whose next due date falls in the requested window.

### `POST /bills`

```json
{
  "name": "Rent",
  "amount_minor": 120000,
  "currency": "USD",
  "category": "housing",
  "kind": "expense",
  "next_due_date": "2026-11-01",
  "frequency": "monthly",
  "active": true
}
```

- `kind`: `expense` or `income`.
- `frequency`: `once`, `weekly`, or `monthly`.
- Success status is `201` with code `FIN_BILL_CREATED`.

The returned entity adds `bill_id`, metadata, and version.

### `PATCH /bills/{bill_id}`

All fields are optional:

```json
{
  "name": "Apartment rent",
  "amount_minor": 125000,
  "category": "housing",
  "next_due_date": "2026-12-01",
  "frequency": "monthly",
  "active": true
}
```

Set `active` to `false` to hide a bill from upcoming-bill and forecast calculations.

## Dashboard and forecast

### `GET /dashboard?month=2026-10`

If omitted, `month` defaults to the current month. Response sections:

```json
{
  "balance": {
    "balance_minor": 240000,
    "currency": "USD",
    "accounts": []
  },
  "summary": {
    "month": "2026-10",
    "income_minor": 500000,
    "spending_minor": 10600,
    "net_minor": 489400,
    "category_totals": {"dining": 10600},
    "top_merchants": [["Bistro 21", 7400], ["Corner Cafe", 3200]]
  },
  "budgets": [],
  "upcoming_bills": [],
  "forecast": {},
  "insights": []
}
```

Known insight types:

- `budget_exceeded`: includes `category` and `amount_minor`.
- `budget_warning`: includes `category` and `utilization`.
- `negative_balance`: includes `date` and `balance_minor`.
- `safety_buffer`: includes `date` and `balance_minor`.

`top_merchants` is an array of two-item arrays: `[merchantName, amountMinor]`.

### `GET /forecast?days=30`

`days` accepts `1..90`. Response:

```json
{
  "days": 30,
  "starting_balance_minor": 240000,
  "daily_discretionary_mean_minor": 1007,
  "daily_discretionary_std_minor": 2369,
  "confidence": 0.8,
  "points": [
    {
      "date": "2026-10-14",
      "projected_minor": 238993,
      "lower_minor": 235958,
      "upper_minor": 242028,
      "scheduled_income_minor": 0,
      "scheduled_expense_minor": 0
    }
  ],
  "alerts": []
}
```

Graph `projected_minor` as the central line and `lower_minor`/`upper_minor` as the confidence area. These are deterministic projections, not guarantees.

## Receipts

### `POST /receipts/scan`

Content type: `multipart/form-data`. Form field name: `file`.

Supported files:

- JPEG (`image/jpeg`)
- PNG (`image/png`)
- PDF (`application/pdf`)
- Maximum size: 10 MiB by default

The server verifies the file signature, not just the extension or declared MIME type.

Example with cURL:

```bash
curl -X POST "$API_BASE/receipts/scan" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -F "file=@receipt.jpg;type=image/jpeg"
```

Response `result`:

```json
{
  "entity_type": "RECEIPT",
  "receipt_id": "uuid",
  "content_type": "image/jpeg",
  "status": "parsed",
  "extraction": {
    "merchant": "Demo Market",
    "transaction_date": "2026-10-13",
    "subtotal_minor": 1000,
    "tax_minor": 80,
    "total_minor": 1080,
    "currency": "USD",
    "category": "groceries",
    "line_items": [],
    "confidence": 0.95
  },
  "transaction_id": "uuid",
  "created_at": "...",
  "updated_at": "...",
  "version": 1
}
```

Status behavior:

- `parsed`: confidence met the threshold and a linked transaction was created.
- `needs_review`: required values were missing or confidence was below the threshold; no transaction was created.

The response never exposes the private S3 key or receipt digest.

### `GET /receipts/{receipt_id}`

Returns the same public receipt shape.

### `PATCH /receipts/{receipt_id}`

Correct fields and optionally create the transaction:

```json
{
  "merchant": "Correct Merchant",
  "transaction_date": "2026-10-13",
  "total_minor": 1080,
  "currency": "USD",
  "category": "groceries",
  "confirm": true
}
```

When `confirm=true`, merchant, date, and positive total must be available. If the receipt already has a transaction, confirmation does not create another one.

## Assistant and conversations

### `POST /chat`

Start a conversation:

```json
{
  "message": "Can I afford a $300 purchase?",
  "conversation_id": null
}
```

Continue a conversation by returning the received ID:

```json
{
  "message": "Set my dining budget to $200",
  "conversation_id": "existing-conversation-uuid"
}
```

Response:

```json
{
  "conversation_id": "uuid",
  "message": "A $300.00 purchase appears affordable...",
  "tool_results": [
    {
      "tool": "get_cashflow_forecast",
      "result": {}
    }
  ]
}
```

The frontend should render `message` as plain text. `tool_results` is diagnostic/structured data and can be used for expandable evidence cards; do not expose private implementation fields.

Chat is currently a normal request/response operation, not SSE or WebSocket streaming. Disable duplicate submission while a request is pending.

### `GET /conversations/{conversation_id}`

Response:

```json
{
  "conversation": {
    "conversation_id": "uuid",
    "title": "Financial conversation",
    "entity_type": "CONV",
    "created_at": "...",
    "updated_at": "...",
    "version": 1
  },
  "messages": [
    {
      "conversation_id": "uuid",
      "message_id": "uuid",
      "role": "user",
      "content": "Can I afford a $300 purchase?",
      "tool_data": {},
      "entity_type": "MSG",
      "created_at": "...",
      "updated_at": "...",
      "version": 1
    }
  ]
}
```

The endpoint returns up to 100 messages in ascending stored order.

## Error handling

| HTTP | Common code | Client behavior |
|---|---|---|
| 400 | `FIN_FORECAST_INVALID`, `FIN_TOOL_INVALID` | Show a corrected-input message. |
| 401 | `AUTH_TOKEN_MISSING`, `AUTH_TOKEN_EXPIRED`, `AUTH_TOKEN_INVALID`, `AUTH_ISSUER_INVALID`, `AUTH_CLIENT_INVALID`, `AUTH_TOKEN_TYPE_INVALID` | Refresh once when appropriate, retry once, then sign out. |
| 403 | `FIN_UNSAFE_ACTION` | Do not retry; show permission/safety message. |
| 404 | `FIN_PROFILE_NOT_FOUND`, `FIN_TRANSACTION_NOT_FOUND`, `FIN_BILL_NOT_FOUND`, `FIN_RECEIPT_NOT_FOUND` | Show empty/onboarding or not-found state. |
| 409 | `FIN_RECEIPT_DUPLICATE` | Use `errors.receipt_id` to open the existing receipt when present. |
| 413 | `FIN_RECEIPT_TOO_LARGE` | Ask the user to capture/compress a smaller file. |
| 415 | `FIN_RECEIPT_INVALID` | Ask for a valid JPEG, PNG, or PDF. |
| 422 | `VALIDATION_ERROR` | Map `errors[].field` and `errors[].message` to form fields. |
| 500 | `INTERNAL_ERROR` | Show a generic retry message and retain `request_id`. |
| 503 | `AUTH_JWKS_UNAVAILABLE`, `AWS_DYNAMODB_ERROR`, `AWS_S3_ERROR`, `AI_GEMINI_UNAVAILABLE` | Offer retry; non-AI dashboard endpoints may still work during Gemini outages. |

Never display raw `errors` as unescaped HTML. Do not automatically retry non-idempotent POST operations except after determining that the original request did not succeed.
